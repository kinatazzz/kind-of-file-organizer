# Учебный проект по Питону - органайзер файлов на устройстве (в моем случае ноут)
Какая была проблема: файлы сохраняются как попало и лежат где попало - вручную заносить в папки не получается (меня хватает так только на пару дней), а в нужные моменты найти файл не удается. Поэтому возникла необходимость автоматизировать сей процесс, чтобы со своим СДВГ хоть как-то структурированно держать файлы и вовремя и при необходимости их находить (а также еще добавлять в чат Кодекса, тк там по работе используется часто и туда вносятся вручную эти файлы для контекста - а с этой автоматизацией можно будет сразу к ним если что обращаться, в общем вот так!)

## Быстрая проверка для преподавателя

Нужен установленный Python 3.9 или новее. Демонстрация использует стандартную
библиотеку Python: устанавливать зависимости, входить в Codex и менять настройки
не требуется. Интернет для демо не используется.

1. На GitHub нажать Code → Download ZIP и распаковать архив.
2. Открыть терминал в папке, где лежит `organizer.py`.
3. Выполнить одну команду.

macOS или Linux:

```bash
python3 organizer.py --demo
```

Windows:

```powershell
py -3 organizer.py --demo
```

Команда сама копирует примеры из `examples`, показывает предварительный план,
выполняет сортировку первого набора и проверяет повторную загрузку.
Используются те же функции сортировки, что и при обычном запуске.

Для каждого запуска создаётся отдельная папка `demo/run-...`. Внутри находятся
входящие `input`, результаты `output`, дополнительные копии `codex` и настройки
`config.json`. В конце программа выводит полные пути. Предыдущие результаты
сохраняются, образцы в `examples` остаются на месте. Анализ через Codex выключен.

Ожидаемые итоги:

| Этап | Перемещено | Дубликатов | Новых дополнительных копий | Ошибок |
| --- | --- | --- | --- | --- |
| Первый набор | 7 | 1 | 2 | 0 |
| Повторная загрузка | 2 | 1 | 1 | 0 |

Проверяемые правила:

| Пример | Результат |
| --- | --- |
| `Питон_задание.txt`, `Питон_копия.txt` | предмет «Программирование на Питоне», копия в папке `codex` текущего запуска, дубликат отдельно |
| `offersagr_отчёт.csv` | `Рабочее/offersagr`, дополнительная копия в папке `codex` текущего запуска |
| файл из Downloads без ключа с расширением `.txt` | `Рабочее/Остальное` |
| файл из Telegram без ключа | `Телеграмовское` |
| `Screenshot_демо.svg` | `Скриншоты` |
| `картинка.svg` | общее `Остальное` |
| `.dmg`, `.crdownload` | остаются во входящей папке |

При повторной загрузке пример с ключом «Питон» имеет то же содержимое,
поэтому отправится в «Дубликаты», а существующая дополнительная копия
будет использована повторно. CSV называется как прежде и имеет тот же размер, но другие данные:
исходный `offersagr_отчёт.csv` сохранится, а новая версия получит имя
`offersagr_отчёт_1.csv` в рабочей папке и тестовой папке `codex`.

SVG — демонстрационные изображения, а `.dmg` и `.crdownload` — текстовые
макеты для проверки исключений. Для повторения демо достаточно снова выполнить
команду с `--demo`: результаты появятся в новой папке.

## Определение категории через Codex

Установить актуальный [Codex CLI](https://learn.chatgpt.com/docs/cli), выполнить
`codex login` и выбрать вход через ChatGPT. Проверить вход: `codex login status`.
API-ключ не нужен. Каждый анализ использует лимиты аккаунта Codex.

```bash
python3 organizer.py --ai
python3 organizer.py --ai --apply
```

`--ai` включает анализ файлов, для которых не найден ключ предмета или проекта.
Скриншоты с известным префиксом и пропускаемые расширения сохраняют свои правила.
Для постоянного включения можно поставить `"enabled": true` в разделе `ai` настроек.

Python извлекает фрагмент содержимого и отправляет его в новую фоновую сессию Codex.
Модель выбирает только из настроенных предметов и проектов; пути папок выбирает Python.
После определения предмета дополнительная копия отправляется в связанный проект Codex,
если у них есть общий ключ. Копирование в папку проекта само по себе не прикрепляет файл к чату.
История других чатов и содержимое всех папок проектов автоматически не передаются.

Поддерживаются TXT, CSV, MD, JSON, LOG, PDF с текстовым слоем, DOCX и XLSX до 10 МиБ.
Передаётся до 12 000 символов: для PDF — начало первых четырёх страниц,
для XLSX — до 30 строк и 20 столбцов первых трёх листов. Формулы не вычисляются.
Видео, изображения и сканированные PDF без текста в этой версии не анализируются.

В `ai.descriptions` можно добавить краткие описания проектов по их названиям,
например `"NPS": "опросы удовлетворённости и готовности рекомендовать сервис"`.
Для проектов с непонятными названиями описание особенно полезно.

При ответе `unknown`, низкой оценке уверенности, отсутствии CLI, таймауте или ошибке
сети программа сообщает об этом и использует обычные папки: «Телеграмовское»,
«Рабочее/Остальное» или общее «Остальное». Оценка уверенности модели не гарантирует
правильность категории; первый запуск лучше сделать без `--apply`.

## Проверки

Для полного набора автотестов нужны библиотеки из `requirements.txt`.
На macOS или Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

GitHub Actions проверяет предпросмотр, перемещение, дубликаты и AI-логику с
подставными ответами. В GitHub не передаются личные файлы, авторизация и реальные
запросы к Codex.

## Личные папки и запуск каждые пять минут на macOS

Скопировать `config.example.json` в `config.local.json` и указать свои папки
в разделах `sources`, `destinations` и `projects`. Для Telegram нужна отдельная
папка загрузок, выбранная также в настройках самого Telegram. В `ai.enabled`
поставить `true`, если нужен анализ содержимого. Личные настройки исключены из Git.

Сначала проверить план распределения:

```bash
python organizer.py --config config.local.json
```

Затем из активированного виртуального окружения подготовить и включить таймер:

```bash
python macos_schedule.py --config config.local.json
mkdir -p "$HOME/Library/LaunchAgents" "$HOME/Library/Logs/kind-of-file-organizer"
cp organizer.plist "$HOME/Library/LaunchAgents/local.kind-of-file-organizer.plist"
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/local.kind-of-file-organizer.plist"
```

`macos_schedule.py` только создаёт файл расписания. Последняя команда включает
запуск с перемещением каждые 300 секунд. Терминал после настройки можно закрыть;
после следующего входа в macOS таймер загрузится автоматически. Во время сна и
выключения компьютера программа не работает. Если предыдущий запуск ещё идёт,
следующее срабатывание пропускается.

Результаты находятся в `~/Library/Logs/kind-of-file-organizer/organizer.log`,
ошибки — в соседнем `errors.log`. Чтобы выключить таймер:

```bash
launchctl bootout "gui/$(id -u)/local.kind-of-file-organizer"
rm "$HOME/Library/LaunchAgents/local.kind-of-file-organizer.plist"
```
