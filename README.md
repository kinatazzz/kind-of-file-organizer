# Мой проектик органайзер файлов

Файлы сохраняются как попало и лежат где попало (у меня СДВГ, поэтому раскладывать их вручную меня хватает на пару дней, а потом в нужный момент получается к сожалению так что  ничего не найти, хочется чтобы цифровой  порядок сам поддерживался, физический тут надо еле поддерживать итак)

Для этого этот собственно проект - он забирает файлы из загрузок, Телеграм и с рабочего стола и раскладывает их по предметам и рабочим проектам. На macOS можно настроить запуск каждые пять минут, плюсом еще я часто пользуюсь Codex по работе (на нем завязаны наши метрики на работе), поэтому для нужных проектов создается дополнительная копия файла в их папке для контекста

## Попробовать на примерах (для защиты, чтобы показать воспроизводимости кода)

Достаточно Python 3.9 или новее. Все примеры уже лежат в репозитории, библиотеки и вход в Codex для этого запуска не нужны

1. На GitHub нажать Code → Download ZIP и распаковать архив.
2. Открыть терминал в папке, где лежит `organizer.py`.
3. Выполнить одну команду.

На macOS перейти в папку можно так: написать в терминале `cd ` с пробелом, перетащить туда распакованную папку из Finder и нажать Enter.

macOS или Linux:

```bash
python3 organizer.py --demo
```

Windows:

```powershell
py -3 organizer.py --demo
```

Программа сама подготовит примеры, покажет план и распределит файлы. Затем добавит второй набор, чтобы проверить повторное скачивание. Сортировка та же, что и при работе с настоящими файлами.

В конце появится путь к папке `demo/run-...`. Внутри:

- `output` — файлы, разложенные по категориям;
- `codex` — дополнительные копии для проектов;
- `input` — входящие папки с файлами, которые программа пропустила;
- `config.json` — настройки этого запуска.

Такой результат должен получиться:

-  При первом запуске программа переместит 7 файлов, из них один — в «Дубликаты». В папках проектов появятся 2 дополнительные копии.
-  При повторной загрузке будут перемещены ещё 2 файла, один из них — в «Дубликаты». Будет создана 1 новая копия для проекта.
-  В обоих случаях ошибок должно быть 0.

В примерах есть учебные файлы с ключом «Питон», рабочий CSV с ключом `offersagr`, файлы без ключей, скриншот и обычная картинка. Также есть два файла с одинаковым содержимым и новая версия CSV с прежним названием и размером. Повтор уйдёт в «Дубликаты», а изменённый CSV сохранится рядом со старым с суффиксом `_1`.

Можно запускать повторно: каждый раз создаётся новая папка, предыдущие результаты и примеры сохраняются. В этом режиме Codex выключен (все действия выполняются внутри тестовой папки)

## Как файлы распределяются

Ключ ищется в начале названия файла, регистр букв не важен. Например, `Питон_задание.txt` относится к предмету «Программирование на Питоне». Сначала проверяется предмет, затем рабочий проект.

Порядок такой:

1. Файл с ключом предмета — в `Образование/Магистратура/Название предмета`.
2. Файл с ключом проекта — в `Рабочее/Название проекта`.
3. Скриншот с началом «Снимок экрана», `Screenshot` или `Screen Shot` — в «Скриншоты».
4. Если совпадений нет и включён Codex, программа пробует определить категорию по содержимому.
5. Если категория так и не определилась: файлы из Telegram — в «Телеграмовское»; CSV, XLSX, TXT, PDF, DOCX и MP4 из загрузок — в `Рабочее/Остальное`; остальные — в общее «Остальное».

Если для проекта указан `codex_folder`, туда создаётся копия. У учебного предмета тоже может быть связанный проект с тем же ключом. Копирование в папку само по себе не прикрепляет файл к чату Codex.

Дубликаты ищутся по содержимому в папке назначения: сначала сравнивается размер, затем SHA-256. Они сохраняются в «Дубликатах». Если совпало только имя, новая версия получает суффикс `_1`, `_2` и так далее. Существующие копии для проектов также проверяются по содержимому.

Программа смотрит только файлы в указанных входящих папках. Вложенные папки, скрытые файлы и ссылки пропускаются. Также пропускаются `.dmg` и временные загрузки: `.part`, `.crdownload`, `.download`, `.tmp`.

## Настроить свои папки

Дальше команды для macOS и Linux. Из папки проекта создать окружение и установить библиотеки для чтения PDF и XLSX:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp config.example.json config.local.json
```

В `config.local.json` указать свои настройки:

- `sources` — откуда забирать файлы;
- `destinations` — куда складывать;
- `subjects` — предметы и их ключи;
- `projects` — проекты, ключи и папки для дополнительных копий;
- `ai.enabled` — использовать ли Codex: `true` или `false`.

Для Telegram нужна отдельная папка загрузок. Её же надо выбрать в настройках самого Telegram. Личные настройки исключены из Git. В JSON нельзя писать комментарии с `#`.

Сначала посмотреть, куда попадут файлы:

```bash
python organizer.py --config config.local.json
```

Затем выполнить перемещение:

```bash
python organizer.py --config config.local.json --apply
```

## Если название ничего не говорит

Для таких файлов можно включить анализ через [Codex CLI](https://learn.chatgpt.com/docs/cli). После его установки выполнить `codex login` и выбрать вход через ChatGPT. Проверить авторизацию — `codex login status`. Используется свой аккаунт и его лимиты, API-ключ не нужен.

```bash
python organizer.py --config config.local.json --ai
python organizer.py --config config.local.json --ai --apply
```

Флаг `--ai` включает анализ для одного запуска. Для постоянной работы нужно поставить `"enabled": true` в разделе `ai` личных настроек.

Python извлекает часть текста файла и отправляет её в новую сессию Codex вместе со списком категорий. Модель выбирает предмет или проект, а папку определяет код. История других чатов и содержимое папок проектов в запрос не добавляются. В `ai.descriptions` можно кратко описать проекты, чтобы категория была понятнее по смыслу.

Читаются TXT, CSV, MD, JSON, LOG, DOCX, XLSX и PDF с текстовым слоем. Лимит файла — 10 МиБ, текста — 12 000 символов. Для PDF берутся первые четыре страницы, для XLSX — до 30 строк и 20 столбцов первых трёх листов; формулы не пересчитываются. Видео, картинки и PDF без доступного текста для анализа не подходят.

Если Codex не ответил, недоступна сеть или ответ не подходит, программа пишет об этом и раскладывает файл по обычным правилам. Результат модели может быть ошибочным, поэтому сначала стоит посмотреть план.

## Запуск раз в пять минут на macOS

После настройки личных папок выполнить из активированного окружения:

```bash
python macos_schedule.py --config config.local.json
mkdir -p "$HOME/Library/LaunchAgents" "$HOME/Library/Logs/kind-of-file-organizer"
cp organizer.plist "$HOME/Library/LaunchAgents/local.kind-of-file-organizer.plist"
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/local.kind-of-file-organizer.plist"
```

Первая команда создаёт расписание, последняя включает его в macOS. После этого программа будет запускаться с `--apply` каждые пять минут, терминал можно закрыть. При следующем входе в систему таймер загрузится снова. Во время сна и выключения компьютера сортировка не работает; если предыдущий запуск ещё идёт, следующий пропускается.

Отчёт о работе: `~/Library/Logs/kind-of-file-organizer/organizer.log`, ошибки — в соседнем `errors.log`.

Чтобы выключить:

```bash
launchctl bootout "gui/$(id -u)/local.kind-of-file-organizer"
rm "$HOME/Library/LaunchAgents/local.kind-of-file-organizer.plist"
```

## Автотесты

Из окружения с установленными библиотеками:

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют выбор папок, предпросмотр, перемещение, дубликаты, деморежим и обработку ошибок. Ответы Codex подставляются в тестах, настоящие запросы не отправляются. Эти проверки запускаются и в GitHub Actions после коммитов.

В коде использованы функции, словари, списки, множества, чтение и запись файлов, обработка исключений. Настройки хранятся в JSON; с путями работает `pathlib`, с копированием — `shutil`, для сравнения содержимого используется `hashlib`. Библиотеки `pypdf` и `openpyxl` нужны для чтения документов при анализе через Codex.
